# Federal Refresh publication contract

Each refresh creates a bounded three-file bundle: `snapshot.json`, `receipt.json`, and canonical `records.jsonl`. The publisher freezes these bytes before verification, validates every record and receipt binding, and publishes the bundle plus its lane pointer in one compare-and-swap Hugging Face commit. It then downloads every committed file at the returned immutable revision and verifies its size and SHA-256 before writing `publication.json` with status `VERIFIED_PUBLISHED`.

Only an exact remote file/path-not-found response proves absence. Repository, credential, transport, rate-limit, server, and concurrent-head errors stop publication. Missing credentials are a failed publication, not a successful skipped run. Lane pointers cannot regress to an older processing timestamp. A failed readback yields no success receipt; the attempted remote commit must be inspected before retry.

The canonical dataset is `SZLHOLDINGS/david-leads-data`. ECHO occupies `snapshots/YYYY-MM-DD/<snapshot_digest>`, `latest/echo-exporter.json`, and the compatibility pointer `latest.json`. Other lanes occupy `snapshots/<lane>/YYYY-MM-DD/<snapshot_digest>` and `latest/<lane>.json`, where lane is `fmcsa`, `form5500`, or `usaspending`. They never overwrite ECHO's compatibility pointer. Previously published content-addressed directories are not overwritten.

ECHO is a streamed official bulk export with a closed facility projection. The source's ZIP-member calendar date is separate from processing time and governs its eight-day freshness window. Other lanes are scheduled bounded captures of the existing official collectors. Their snapshots disclose source method, territory coverage, processing time, exclusions, and query limits; they are not represented as complete national bulk products.

The Space reads and verifies these dataset snapshots without calling the four federal providers during a user request. It never substitutes samples. Missing, stale, malformed, or tampered snapshots remain unavailable. Session receipts are minted locally for the served projection; stored snapshots do not reuse receipt identifiers from a different process.

PurIQ v1 receipts are standalone genesis receipts and explicitly `UNSIGNED`. Their payload hashes are tested against the vendored immutable JavaScript reference recorded in `tests/vendor/puriq_v1/UPSTREAM.json`. Payload integrity is not signer authentication or a chain across refreshes. GitHub OIDC attestation of the snapshot manifest is separate evidence retained in the workflow artifact. The manifest binds source, parser revision, policy, record count, ordered record root, and exact JSONL bytes.

The workflow runs daily, admits only current protected-main source, serializes lane publication, pins actions and publisher dependencies, scopes `HF_TOKEN` to the publishing step, and retains bounded manifest/receipt/publication/attestation evidence for 90 days. Raw upstream archives and record files are not copied to GitHub artifacts. Space deployment verifies all four complete fresh bundles before provider mutation; missing data preserves the existing deployment. After first publication, the owner dispatches deployment from current main. The canary runs its offline contract on PR/push and probes live only after successful deployment, on its schedule, or by manual dispatch. Source merge, workflow success, dataset publication, Space deployment, and witnessed runtime remain distinct proof states.
