# David V2 operator workflow

This extends the existing application at `/`, FastAPI server, login, PostgreSQL
deployment and protected release pipeline. Select **Operator research**, sign in,
and open the assigned workspace. Public market research remains the default tab.

## Deployment inputs

The application must use the non-owner runtime `DAVID_DATABASE_URL`. The migration
workflow separately uses `DAVID_DATABASE_ADMIN_URL` in its existing protected
environment. `/readyz` now requires both legacy deal-desk persistence and the
evidence runtime-role/schema contract. A privileged database login fails admission.

Install a reviewed operator policy with either `DAVID_OPERATOR_POLICY_PATH`
(absolute private file) or `DAVID_OPERATOR_POLICY_JSON` (Space secret). An explicit
path takes precedence. The schema is illustrated in
`ops/operator-policy.example.json`; the checked-in example grants nobody access.
Each authorized operator must have `read`, a real tenant, a purpose of
`organization_research`, an expiry and only the required actions. Existing
`DAVID_USER`, `DAVID_PASS`, and `DAVID_ACCESS_KEY` remain the authentication inputs.
Policy revision/digest changes invalidate previously bound task authority.

DOL source admission independently requires a reviewed `szl.david.dol-admission/v1`
policy via `DAVID_DOL_POLICY_PATH` or secret `DAVID_DOL_POLICY_JSON`, and its HMAC key
via `DAVID_DOL_SIGNING_KEY_FILE` or secret `DAVID_DOL_SIGNING_KEY`. The key must match
the publisher's `DOL_SNAPSHOT_SIGNING_KEY`. No key or source grant is generated by
the application. Policy fields are exact: `schema`, `source_id`, `policy_revision`,
`review_reference`, `expires_at`, `rights`, `allowed_fields`, `purpose`,
`jurisdictions`, `snapshot_revision`, and `classifications`. Source ID is
`dol-form5500-benefit-timing`; snapshot revision is an immutable 40-character Hub
commit. Rights must explicitly cover collect, research, public_display,
redistribute and train. Approving research does not approve the other operations.
Each admitted record needs a reviewed organization classification bound to its
normalized record hash, review reference and expiry. Legal-name suffixes do not
establish an organization. A changed/removed key requires new snapshot admission.

These reviewed values must come from the owner's actual source and operator
decisions. Synthetic fixtures under tests are not deployment configuration.

## End-to-end operation

1. Check the immutable snapshot. Source health records transport, schema, signature,
   completeness and freshness separately from configuration and policy. A failed
   attempt preserves the timestamp of the last successful observation.
2. Admit a source reference: source ID, filing ID and immutable snapshot revision.
   The server reads verified, minimized snapshot bytes and current reviewed policy.
3. Review the organization relation and build a deterministic evidence brief. The
   brief includes source facts, dates, uncertainty and unresolved counter-evidence.
   Snapshot publication is distinct from an unknown original filing-publication time.
4. Review the brief, obtain a server clearance and create a manual research task.
   Every mutation binds the expected scope epoch; stale decisions require reload.
   Newer rejections supersede prior approvals. Client READY flags create no authority.
5. Record outcomes, counter-evidence, corrections or suppression. Corrections
   invalidate dependent evidence/briefs/clearances/tasks and cancel pending delivery.
   Invalidated or no-longer-permitted payloads are withheld from the workspace.

Tasks are durable manual research records. There is no email, telephone, outreach,
underwriting or external CRM sender. Outbox leases have fencing and explicit
DELIVERY_UNKNOWN handling; they do not promise exactly-once external delivery.
Evidence digests are `LOCAL_SHA256_UNSIGNED`; HMAC snapshot verification is not an
independent signature or a release receipt. Release attestation remains separate.

## Validation and release

Run `python qa/run_required_tests.py tests` against a disposable PostgreSQL service
identified by `DAVID_EVIDENCE_TEST_DSN`, then `node --test tests/*.test.mjs`. The test
bootstrap creates a separate least-privilege runtime login. CI refuses zero tests
and skipped required tests. The release-contract utility only reports
`CONTRACT_COMPLETE_UNVERIFIED`; it does not authorize deployment.

Merge through the protected source process, run the exact-current-main schema
migration, and allow the existing successful-migration publication chain to proceed.
Verify copied bytes, the attestation and `/api/build-info` against that same source
revision after restart. A successful classifier with skipped publication is not a
deployment. Do not approve an older waiting migration after main has advanced.
